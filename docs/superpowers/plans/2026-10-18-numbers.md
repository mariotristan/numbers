# Bruno's Numbers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A bilingual, offline, installable math-practice game for 2nd–4th graders. A 14-level path of 10-question rounds, coins, a shop for Bruno outfits and stickers, and an animated "here's why" explanation for every wrong answer.

**Architecture:** This starts from the Bruno-family template (`~/.claude/skills/building-kids-learning-games/templates/`). All math logic is in pure, RNG-injected modules under `js/math/`: problem generators, answer choices, number-pad entry and explanation steps. The round state machine (`js/round.js`) and saved progress (`js/progress.js`) are pure too. Screens are thin DOM renderers driven by the template's `ctx` router. Blocks, Bruno's outfits and sounds are drawn or synthesized in code.

**Tech Stack:** Plain HTML/CSS/JS ES modules, no build step, no runtime dependencies. Tests use `node --test`. Hosted on GitHub Pages as a PWA.

**Spec:** `docs/superpowers/specs/2026-10-18-numbers-design.md` (read it first; this plan refers to its level table and explanation table rather than copying them).

## Global Constraints

- No framework, bundler, runtime dependency, CDN, web font, analytics or CI. `package.json` exists only for `"test": "node --test"`.
- All paths are relative (the game is served under `/numbers/`).
- Every user-visible string goes in `js/data/strings.js` with non-empty `en` and `es` and the same `{placeholders}`. The Spanish is neutral Latin American and gender-neutral toward the child.
- No emoji in `js/ui.js`, `js/screens/*`, `js/blocks.js` (enforced by `tests/emoji-guard.test.js`). Use Phosphor icons via `icon()`.
- `CACHE_PREFIX = "numbers-"`, `CACHE = "numbers-v1"`. Activate deletes only `key.startsWith(CACHE_PREFIX) && key !== CACHE`. `STORAGE_KEY = "bruno-numbers"`.
- Code and pages are network-first. Only png/webp are cache-first.
- Buttons are real `<button>`s with a localized `aria-label` when they show no text. Targets are ≥ 64 px, layouts work from 360 px wide, and `prefers-reduced-motion` stops all animation.
- Colors by place value everywhere: hundreds `#e8453c` (red), tens `#2f80ed` (blue), ones `#27ae60` (green).
- `ROUND_LENGTH = 10`, `PASS_SCORE = 7`, `MAX_BONUS = 3`, `PERFECT_BONUS = 5` coins, sticker price 10, closet prices 15–60.
- Stars from score: 10 → 3, 8–9 → 2, 7 → 1, < 7 → 0.
- Bruno never says "wrong"/"no"/"incorrecto" in any string.
- Commit as `mariotristan <mariotristan@gmail.com>`. Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never push without asking the user.
- Keep every template pitfall fix: speech utterance reference, `speakable()`, `view.isConnected` checks in timeouts, storage probe, `validate()`, double-tap guard, SW Range/206.

## Review Focus

1. **Language switch or Bruno re-render in the middle of a round or explanation.** The round, current question, typed digits and explanation step must survive `ctx.rerender()`. They live in `ctx.params`, never in screen-local closures only. (Test: Task 5 `round survives JSON round-trip`. Manual check: Task 12.)
2. **Number pad edge inputs.** Pressing Check with nothing typed, typing more digits than the boxes hold, leading zeros ("085"), and delete on an empty entry must never throw or score a blank as wrong. (Tests in Task 3.)
3. **Rounds that can't avoid last round's problems.** Level 8 has only a few dozen distinct problems. `buildRound` must relax the "avoid" list rather than loop forever or return fewer than 10. (Test in Task 2.)
4. **Corrupt or old saved data.** A worn item that isn't owned, negative or fractional coins, unknown sticker ids, a `bestScore` of 99, or levels unlocked out of order must be sanitized, never crash. (Tests in Task 6.)
5. **Leaving mid-round.** Back during a correct-answer delay or a running explanation animation must not re-render a dead screen or double-award coins. Coins already earned stay earned. (Tests: Task 5 `answer is ignored while awaiting next`. Manual check: Task 12.)

### Task 5: Round state machine

**Files:**
- Create: `js/round.js`
- Test: `tests/round.test.js`

**Interfaces:**
- Consumes: `buildRound`, `ROUND_LENGTH`, `MAX_BONUS`, `PERFECT_BONUS` (Task 2).
- Produces (all pure, plain-JSON state):
  - `startRound(levelId, rng, avoidKeys) → Round` = `{ level, problems, index, phase: "question"|"feedback"|"explain"|"done", results: boolean[], bonus: Problem[], bonusIndex, inBonus: boolean, coins, explainStep: 0, awaitingNext: boolean }`
  - `current(round) → Problem|null`
  - `answer(round, value) → { round, correct, coinsDelta }`: ignored (returns same round, `coinsDelta: 0`) while `awaitingNext`. Correct gives +1 coin and phase `"feedback"`. Wrong gives phase `"explain"`. A wrong answer in the main round queues the problem for bonus (max `MAX_BONUS`).
  - `nextStep(round) / prevStep(round)` (explanation step index), `advance(round) → Round` (next question, then the bonus queue, then `"done"`).
  - `summary(round) → { score, stars, coins, perfect, problemKeys }`. `coins` includes `PERFECT_BONUS` when perfect, and that bonus is included in the `coinsDelta` of the final advance.
  - `starsFor(score) → 0..3`.
